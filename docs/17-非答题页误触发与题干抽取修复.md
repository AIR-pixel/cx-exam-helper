# 17 - 非答题页误触发与题干抽取缺陷修复

> 时间：2026-11-24 21:00–21:15
> 设备：Redmi M2101K9C / Android 17 / HyperOS，学习通 7.0.4 (10995)
> 服务端：answer-server v2.1，engine=qoder（DeepSeek-Flash）

## 结论

真机联调时发现四个缺陷，全部已修并留断言。最严重的是**非答题页会打模型**：
学习通登录页被当成一道简答题送给 LLM，白烧一次调用，还把"该内容并非课程题目"
糊到叠层上。修复后同一屏幕 28ms 返回 `source=none`，不再调用模型。

| # | 缺陷 | 现象 | 修复 |
|---|---|---|---|
| 1 | 服务端无「是不是题目」判据 | 登录页清洗后剩一行「我已阅读并同意…」，`splitQuestions` 当成无选项简答题 → 送模型（2818ms），入缓存 | `looksLikeQuestion()` + `EXAM_CHROME_RE`，`parseScreen`/`parseStructured` 都过闸 |
| 2 | 设备端 OCR 兜底不过闸 | a11y 判 `usable=false` 后无条件 `screencap` 上送 210KB 图，模型回废话 | `isExamPage()` 闸门 + `source=none` 二次拦截 |
| 3 | 重试链并发 | 登录页 `windowContentChanged` 一秒多次，多条 6 次重试链同时跑，日志 `attempt#3/#5/#1` 乱序 | `scanGen` 代次作废旧链；日志按内容变化去重 |
| 4 | 简答题题干抽成输入框 hint | `STRUCT stem=在此输入你的答案`，模型回"请提供具体题目" | `isPlaceholder()` 排除占位文案；带题号/分值的行优先于「最靠下的长文本」 |

## 缺陷 1：服务端缺题目页判据

### 复现

```powershell
$loginText = "浏览模式`n客服`n登录`n手机号/超星号`n密码`n忘记密码?`n我已阅读并同意学习通《隐私政策》和《用户协议》`n新用户注册`n手机号快捷登录`n其他登录方式"
$body = @{ question = $loginText } | ConvertTo-Json -Compress
Invoke-RestMethod -Uri "http://127.0.0.1:18888/answer" -Method Post `
  -ContentType "application/json; charset=utf-8" `
  -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
```

修复前：

```json
{"answer":"该内容为同意《隐私政策》和《用户协议》的确认表述，并非课程题目。…",
 "source":"qoder","type":"short","ms":2818,
 "question":{"stem":"我已阅读并同意学习通《隐私政策》和《用户协议》","options":[],"type":"short"}}
```

修复后：

```json
{"answer":"未识别到题目（当前页面不是答题页）","source":"none","type":null,
 "question":null,"stableKey":"","ms":4}
```

### 判据设计

`answer-core.mjs` 新增 `looksLikeQuestion(q, {examPage})`，按可信度分档：

1. 选项 ≥2 个 → 选择题，一定是题
2. 有题型标签（`单选题`/`简答题`…）→ 标签只出现在题目页
3. 命中题干特征正则 → 问句 / 「下列…哪」/ 分值 / 填空空位 / 题干动词
4. 考试页兜底（`examPage=true`）→ 有实质内容就算题，但排除纯界面标签

`EXAM_CHROME_RE` 判定考试页：

```js
/(交卷|答题卡|上一题|下一题|剩余时间|倒计时|保存[^\n]{0,6}提交|提交试卷|共\s*\d+\s*题)/
```

### 踩坑：不能看拼接总长

`splitQuestions` 在无选项时把**整屏所有行**用空格拼成一个 stem。首页/课程列表
拼出来几十个字，`stem.length < 8` 这类长度判据完全失效 —— 实测
「首页 消息 课程 我 我的课程 计算机网络…」被判成简答题。

改成按 `\s+` 切段逐段判，只看**单段**是否命中题干特征。

### 踩坑：裸「计算」误伤课程名

第一版题干动词表里放了裸 `计算|分析|比较|说明|解释`，结果课程名
「计算机网络」命中「计算」，首页又被判成题目。收窄为：

```js
/(简述|简答|试述|论述|阐述|名词解释|问答|默写|背诵)/,
/(计算|分析|比较|说明|解释|判断|求解|证明|推导)(并|下列|以下|下题|该|此|其|：|:)/,
```

## 缺陷 2：设备端 OCR 兜底不过闸

`ReaderService.attempt()` 原来：

```java
if (!usable) {
    if (ToggleStore.appOn()) handleWithOcr(text);   // 无条件截屏上送
    return;
}
```

`looksLikeQuestion()` 正确判了 `false`，但兜底没再校验。真机日志（修复前）：

```
AnsReader: give up after 6 attempts, last=浏览模式|客服|登录|…|其他登录方式
AnsReader: OCR fallback: sending 210KB image
[qoder] short q="我已阅读并同意学习通《隐私政策》和《用户协议》"
```

修复后：

```java
if (ToggleStore.appOn() && isExamPage(text)) {
    handleWithOcr(text);
} else {
    Log.d(TAG, "OCR fallback skipped: not an exam page");
    Bus.publishStatus("未识别到题目（当前不是答题页）", "off");
}
```

真机验证：

```
AnsReader: give up after 6 attempts, last=浏览模式|客服|登录|…
AnsReader: OCR fallback skipped: not an exam page
```

服务端日志只有一行 `[none] not a question page examPage=false candidate="…"`，
没有 `[qoder]` 调用。

## 缺陷 3：重试链并发

`scheduleScan()` 只能 `removeCallbacks(pending)` 取消**还没跑**的那一跳。
已经启动的重试链内部用 `h.postDelayed` 排下一跳，取消不掉。登录页
`windowContentChanged` 一秒来好几次，于是多条链同时跑，日志乱序：

```
attempt#1 windows=1 chars=72 usable=false
attempt#3 windows=1 chars=72 usable=false
attempt#5 windows=1 chars=72 usable=false
attempt#2 windows=1 chars=72 usable=false
```

修法：`scanGen` 代次。`scheduleScan` 每次 `scanGen++`，重试链的下一跳
发现代数变了直接 `return`。

顺带压日志：只在整屏文本变化时打 `attempt#N`。修复后登录页从几十条降到
25 行（含 mock 遗留），重试序列干净递增。

## 缺陷 4：简答题题干抽成输入框 hint

### 现象

Mock 第 5 题（简答）：

```
STRUCT stem=在此输入你的答案 opts=0 type=简答题
answer src=qoder type=short => 未收到具体题目内容，请提供完整题目后再作答。
```

真实 DOM：

```
5.（5分）简述为什么 UDP 不保证可靠传输却仍然被大量实时业务采用。  @33,297
在此输入你的答案                                              @33,486
```

### 根因

`groupNodes()` 取「选项区上方最靠下的长文本」当题干，门槛 `length >= 8`：

- 题干「5.（5分）简述…」长度够，但**位置在 hint 上方**
- hint「在此输入你的答案」9 字过门槛，**位置更靠下** → 被选中

且 `isEditable()` 救不了：mock 的答题框在 WebView 里渲染成普通
`android.widget.TextView`（`editable=false`），属性上完全看不出是输入框。

### 修法

三层：

1. `collectNodes` 记录 `isEditable()`（真 EditText 场景有效）
2. `isPlaceholder()` 按文案排除：`在此输入` / `请输入` / `点击输入` / `输入你的答案` / `填写答案`
3. 带题号/分值的行（`STEM_MARK`）**优先**，只有无标记行才走「最靠下的长文本」

```java
String markedStem = ""; int markedTop = -1;
for (TextNode n : nodes) {
    if (n.editable) continue;
    if (firstOptTop > 0 && n.top >= firstOptTop) continue;
    if (isChromeText(n.text)) continue;
    if (isPlaceholder(n.text)) continue;
    if (STEM_MARK.matcher(n.text).find()) {
        if (markedStem.isEmpty() || n.top > markedTop) { markedStem = n.text; markedTop = n.top; }
        continue;
    }
    if (n.text.length() < 8) continue;
    if (stem.isEmpty() || n.top > stemTop) { stem = n.text; stemTop = n.top; }
}
if (!markedStem.isEmpty()) stem = markedStem;
```

`STEM_MARK`：

```java
"^\\s*(?:第\\s*\\d{1,3}\\s*题|\\d{1,3}\\s*[.、．)）])|[(（]\\s*\\d+(?:\\.\\d+)?\\s*分\\s*[)）]"
```

### 验证

```
STRUCT stem=5.（5分）简述为什么 UDP 不保证可靠传输却仍然被大量实时业务采用。 opts=0 type=简答题
answer src=qoder type=short ms=2586 => UDP 不保证可靠传输，但实时业务更重视时延和抖动…
```

## 断言

`test-core.mjs` 新增 §15「题目页判定」，45 项：

- 6 个非题目页（登录/首页/课程详情/签到/消息/个人中心）必须 `ok=false`、
  `primary=null`、`stableKey=''`，且留 `rejected` 供排查
- 5 个真题目页必须 `ok=true`
- `examPage` 标识正确
- 结构化路径同样拦截（登录页协议 / 短标签）
- `looksLikeQuestion` 直接判据 11 项，含「计算机网络」「数据分析」不误判的回归

全量：`test-core` 170 + `test-cache` 25 + `e2e-server` 34 + `e2e-qoder` 24 = **253 项全绿**。

## 遗留

- 学习通真实考试页仍未验证（需账号登录）。当前所有题目页判据基于 Mock +
  真机登录页/首页实测，真实考试页的 DOM 结构需登录后复验。
- `EXAM_CHROME_RE` 依赖「交卷/答题卡/上一题/下一题」等文案。若学习通某类
  考试页（如小程序版）没有这些元素，OCR 兜底会被误挡 —— 但选项/题型标签/
  题干特征三档仍能独立放行，只有纯图片题会受影响。
- 作业页（非考试页）没有「交卷」，但有「提交」。`EXAM_CHROME_RE` 里的
  `保存[^\n]{0,6}提交` 和 `提交试卷` 覆盖了部分场景，仍需真机复验。
