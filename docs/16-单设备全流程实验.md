## 四、这次踩的四个坑（全部是新发现，之前文档没记）

### 坑 1：`assets/xposed_init` 没打进 APK → 模块"装了但完全不生效"

`build-module.ps1` 只做了 `aapt2 link`，没有 `-A assets`。结果 APK 里只有
`AndroidManifest.xml / resources.arsc / classes.dex`，**没有 `assets/xposed_init`**。
LSPosed 靠这个文件找入口类，缺了它 → 模块包一切正常、scope 正常、日志一行不报，
hook 就是不上。

修复：
```powershell
& "$BT\aapt2.exe" link ... --auto-add-overlay -A (Join-Path $HERE 'assets')
```
验证：
```
AndroidManifest.xml  2572
assets/xposed_init   30      ← 必须有
classes.dex          8340
```

### 坑 2：包 `stopped=true notLaunched=true` → LSPosed 查不到包信息

```
W/LSPosedService  Failed to find package info of com.air.skipmodule
```
装了但从没启动过的包带 `FLAG_STOPPED`。LSPosed 在 fork 目标进程时要用 `PackageInfo`
校验模块，对 stopped 包查不到 → 静默丢弃。

修复：给模块加一个空壳 `Main` Activity，装完 `am start` 一次：
```
before: stopped=true  notLaunched=true
after : stopped=false notLaunched=false
```

### 坑 3：stub 的 `hookAllMethods` 返回类型写错 → `NoSuchMethodError`

stub 里写的是 `public static XC_MethodHook.Unhook hookAllMethods(...)`，
真实 LSPosed 是 `public static Set<XC_MethodHook.Unhook> hookAllMethods(...)`。
javac 阶段 stub 自己说了算，编得过；运行期 dex 里的方法描述符是
`(...)Ljava/util/Set;`，而调用点引用 `(...)LXC_MethodHook$Unhook;` —— 对不上：

```
NoSuchMethodError: No static method hookAllMethods(Ljava/lang/Class;Ljava/lang/String;
  L…/XC_MethodHook;)L…/XC_MethodHook$Unhook; in class L…/XposedBridge
```

**stub 的方法签名必须逐字节照抄真实 API，包括泛型擦除后的返回类型。**

### 坑 4：Android 17 的 `ViewRootImpl.setView` 签名变了

```
NoSuchMethodError: android.view.ViewRootImpl#setView[class android.view.View,
  class android.view.WindowManager$LayoutParams]#exact
```
用 `findAndHookMethod` 锁精确签名必然失败，而且**异常会把同一个 try 块里后面的 hook 全部带掉**。

修复两条：
1. 只按方法名 `hookAllMethods`，不锁签名；
2. 每个 hook 各自 try-catch，用 `hook(cls,name,cb)` 包装，互不影响。

修复后日志：
```
[SkipModule] hooked setView
[SkipModule] hooked performTraversals
[SkipModule] hooks installed
[SkipModule] SKIP applied to Surface(name=VRI-#191)/@0x30a8a14
```

### 附带：重启会扣光 A 槽 retry → 卡 fastboot

```
slot-retry-count:a: 0
slot-unbootable:a: yes
```
救援（本次实测有效，`retry` 0→7，50 秒开机）：
```
fastboot --set-active=a
fastboot reboot
```
**教训：调试期尽量不重启。** 模块/DB 改动都能靠
`am force-stop` + 重绑 a11y 服务触发 LSPosed 重新 fork 目标进程，不用重启。

## 五、另外两个纠错

### 锁屏未解锁 ≠ 包损坏

设备停在安全锁屏（`dumpsys trust` 里 `deviceLocked=1`）时，CE 存储未挂载：
- `/data/user/0/com.air.mpprobe` 不存在
- 所有第三方 app 的 `pm resolve-activity` 返回 `No activity found`
- `am start` 报 `Error type 3 … does not exist`
- a11y 服务 `Bound services:{}`，日志里 `Ignoring non-encryption-aware service`

这一整套现象**看起来像包被卸载/损坏**，实际只要解锁就好：
```
input keyevent KEYCODE_WAKEUP
input swipe 540 2000 540 700 150   # ×2
```
解锁后同一命令立刻成功。**排查顺序里必须先查 `isKeyguardShowing`。**

### 标志文件路径：`/sdcard` → app 私有目录

原来用 `/storage/emulated/0/skip.flag`。Android 13+ 上 app 读 `/sdcard` 需要存储权限，
且 SELinux 会以 `shell_data_file` 拒绝。改成：
```
/data/data/com.air.mpprobe/files/skip.flag
```
同域 `app_data_file`，模块进程（跑在目标 app 里）直接可读，只需 root 写入 + `chown u0_a205`。

## 八、UI 迭代二：浅灰透明背板 + 超长答案自动滚动（11-23 23:1x）

### 背景

- **背板去染色**：用户要求背板不要按答案来源（真模型/缓存/错误）变颜色，只要"单纯的浅灰 + 透明"，
  不改题面可见性。`paintCard()` 重写为固定 `#1AE0E0E0`（≈10% 浅灰）+ 2dp `#FF9E9E9E` 描边 + 14dp 圆角，
  删掉 source→颜色 switch。
- **长答案自动滚动**：浮层 `NOT_FOCUSABLE|NOT_TOUCHABLE`，用户摸不到滚动条。长答案必须程序自滚：
  `scheduleAutoScroll()` 在文本放不下时启动状态机（16ms 步进 6px 向下 → 底部停 1800ms → 回顶 → 顶部停 2500ms → 循环），
  `hide()` / 新 render 时取消。短答案（放得下）不滚动、零开销。
- **label 乱码修复**：`AndroidManifest.xml` 从 GBK 旧文件修成 UTF-8 `答案助手`（重建后设备端
  `Bound services:{Service[label=答案助手,…}` 证实）；附带的教训是 **aapt2 在 Windows 按本地代码页
  （GBK）回显二进制 XML 字符串**，验证乱码要按原始字节搜 UTF-8 needle，不能信终端回显。

### 验证（全部走缓存 / LONG_TEST 兜底引擎，**零 LLM 额度消耗**）

| 项 | 方法 | 证据 |
|---|---|---|
| 浅灰背板（Q1 单选） | 走缓存，`OVERLAY[900x174] 题库缓存 · 单选 · 58ms` | `evidence/grey-q1.png` |
| 浅灰背板（Q3 判断） | 走缓存，`OVERLAY[780x174] 题库缓存 · 判断 · 23ms` | `evidence/grey-q3.png` |
| 长答案触发滚动 | `LONG_TEST=1` 兜底引擎返 ~4000 字，`OVERLAY[1000x1438]`（触顶 480dp） | 三连拍 2s 间隔 |
| 滚动确实在动 | 三张连拍像素 diff：**44.72% / 41.39% / 46.20%** | `evidence/scroll-a/b/c.png` |
| 短答案不滚动 | Q1 缓存短答案连拍 diff **0.00%** | `evidence/short-a/b.png` |
