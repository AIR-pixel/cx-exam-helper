## 二、真 AI 引擎（①）

### 2.1 为什么走 qoder 而不是 OpenAI key

原本计划两条路：DSH ACP + qoder 登录态（当时 502 `RESOURCE_LIMIT`），或配 OpenAI 兼容 key。
两条都没用上——直接复用了本机 DSH 已装好的 `@dmh2002/dsh-connect-qoder` 插件里的
`QoderUpstreamClient`。这个客户端已经对着 live gateway 验过签名/令牌交换，重写一遍 cosy 协议纯属浪费。

### 2.2 实现

`research/_probe/engine-qoder.mjs`：

```js
// 动态 import 插件主 bundle（lib/host-heartbeat-_xDi4sbQ.js）
const mod = await import(pathToFileURL(PLUGIN_LIB).href);
// 导出：b=QoderUpstreamClient, y=QODER_REGIONS, Z=deriveFingerprint
const client = new mod.b(credential, region);
await client.chatStream(credential, modelKey, messages, { onDelta, signal });
```

PAT 来源（按序尝试）：环境变量 `QODER_PAT_CN` / `QODER_PAT_GLOBAL` / `QODER_PAT`
→ `~/.dsh/.qoder-accounts.cn.json` / `.global.json`。

### 2.3 硬依赖：ESM 解析钩子

插件 bundle 顶层 import 了 `@deepseek-ai/dsh-atomic-write`，在普通 node 进程里解析不到
（`NODE_PATH` 对 ESM 无效）。解法是两个 loader 文件：

- `dsh-resolve.mjs` —— 把 `@deepseek-ai/*` / `openai` 重定向到 DSH 自带的 `node_modules`
- `dsh-resolve-register.mjs` —— `register('./dsh-resolve.mjs', ...)`

**启动服务必须带钩子**：

```powershell
node --import ./dsh-resolve-register.mjs answer-server.mjs
```

漏了就是 `ERR_MODULE_NOT_FOUND`。

## 三、解析器：三个真 bug（④ 的一部分）

接上真模型后立刻暴露三个解析器 bug。都是「离线 heuristic 恰好没踩到」的类型。

### Bug 1 · 题型词被当成界面装饰整行吞掉

`UI_CHROME` 集合里列了 `'单选题','多选题','判断题','填空题','简答题'`。
学习通把题型单独排一行（题号行 / 分分行 / 题型行 / 题干行），于是：

```
5.（4分）
多选题              ← UI_CHROME 命中，整行丢弃
下列哪些属于HTTP请求方法
A. GET …
```

题干和选项里都没有「多选」字样 → `detectType` 判 `single` → 模型按单选答，只回一个字母。
实测「下列哪些属于 HTTP 请求方法」被答成 `A GET`。

**修法**：
1. 题型词从 `UI_CHROME` 移除（它们是信息，不是装饰）。
2. `stripPrefix` 拆成 `stripPrefixDetailed(line) → {line, typeLabel}`，
   把被剥掉前缀里的题型词捞出来。
3. `cleanLines` 输出 `typeLabels: Map<行下标, 题型词>`；`多选题` 单独成行时
   先挂起（`pendingType`），等下一行真内容出现再一起带走。
4. `detectType` 最先读 `q.typeLabel`，比文本推断更权威。
5. 无选项的兜底路径（填空/简答）也要带 `typeLabel`。

### Bug 2 · 题型标签正则无边界，误吃题干

修完 Bug 1 后新增一条回归断言失败：`多选题和单选题有什么区别？` 的题干被剥成
`和单选题有什么区别`。

原因是题型标签正则 `^(?:单选题|多选题|…)\s*…` 没有右侧边界。

**修法**：加否定前瞻——标签后紧跟这些字说明它在句中，不能剥：

```js
(?!\s*(?:和|与|或|及|、|的|等|有|是|比|跟|区|之|对))
```

不能简单要求「标签后必须是空白或行尾」——那样 `单选题下列关于`（无空格，a11y 常见）
又剥不掉。

### Bug 3 · 简答题 JSON 不解包 + 双层套娃

模型答简答题返回 `{"text":"…"}`，但 `parseAnswerText` 只认 `answer` / `indices` / `index` /
`answers`，没有 `text` 分支 → 整串 JSON 被当正文塞进 `params.text`。

更糟的是 `renderAnswer` 也没有 `params.text` 分支，最后输出成
`{"text":"{\"text\":\"TCP与UDP的主要区别…\"}"}`。

**修法**：
1. `parseAnswerText` 加 `j.text` 分支，并递归解套（模型会自己套娃，最多 3 层）。
2. `type==='short'` 收到 `answers` 数组时按行拼接，不再退化成 `selectedIndex:0`。
3. `renderAnswer` 加 `p.text` 直出分支。

### 附带修的一个崩溃

`answer-core.mjs` 的 CLI 入口判断 `process.argv[1].replace(...)` 在 `node -e` 下
`argv[1]` 是 `undefined` → `TypeError`。改成 `pathToFileURL(_argv1).href` 比较。

## 四、题库缓存（③）

`answer-cache.mjs` 用 `node:sqlite`（Node 24 内置），表结构：

```sql
questions(qkey PK, stem, options_json, type, answer_json, source, created_at, last_hit_at, hits)
meta(k, v)
```

`qkey` = `normalizeForHash(q)`：题干去空白去标点小写 + 选项文本同法处理后 sha256 前 32 位。

实测改写标点仍命中：

```
"下列关于TCP三次握手"  vs  "下列关于 TCP 三次握手。"
→ 同 qkey，source=cache，答案完全一致
```

简答题**有意不入库**：答案长、没有复用价值、且每次表述不同，去重评分不高。
`/stats` 里因此看到 5 道题只落 4 条。

## 六、手机端还没跟上

`research/_probe/answer-app/src/com/air/answer/ReaderService.java` 里读答案是
朴素 `"answer"` 子串提取，只认旧返回格式。需要改成消费 v2 形状：

```json
{"answer":"D 以上都正确","source":"qoder","type":"single",
 "question":{"stem":"…","options":[…]},"screenHash":"…","ms":1794}
```

具体改动：按 `type` 决定渲染宽度（简答要能滚），按 `source` 上色区分
（qoder 绿 / cache 灰 / none 红 / error 红闪），`screenHash` 用来避免同屏重复渲染。
